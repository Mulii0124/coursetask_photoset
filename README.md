## 视觉与动效规则

- **影像节奏**：全站仅首屏与「重点故事」使用满屏影像；其余区块每屏最多一张主图，
  拼贴不超过两张。影像密集区之间插入纯文字或大留白章节，形成
  「影像—留白—文字—影像」的阅读节奏。
- **图版不铺满**：系列页的单张照片限制在 `min(1040px, 70vw)` 并居中，
  两侧永远留白；竖幅图另收一档到 `min(660px, 46vw)`，保证一张竖片的高度
  不会超出屏幕。窄屏（≤760px）放宽到 `86vw` / `74vw`，让照片在手机上仍占主体。
  只有首屏与重点故事是满屏影像。
- **首屏推页**：首屏使用 `position: sticky` 固定在视口内，下一内容区从底部上推覆盖它。
- **系列目录是真实超链接**：目录里的每一项都是指向对应系列页的 `<a>`，
  鼠标悬停或键盘聚焦时右侧预览切换到该系列的封面，点击直接进入该系列；
  图片下方的「进入系列 →」始终指向当前预览的系列。
- **图片切换**：系列目录切换时，旧图以 `scaleY(1)→0`（变换原点在上边缘）向上收缩，
  新图以 `scaleY(0)→1`（变换原点在底边缘）从底部展开。
- **文字进入**：所有文字与内容通过 `clip-path: inset()` 裁切进入，
  不使用普通淡入，也不使用 3D 翻页。
- **翻页**：页面之间用竖向幕布擦除（`scaleY`）衔接，而非淡出淡入。
- **卷与分隔**：「初」系列在自摄的六帧之后插入一道分隔页「卷二 / PART TWO · 花与影」，
  说明后八帧同样出自摄影师之手，画面上的「Pe.Daphine vortex 2023」是摄影师自打的记号。
- **满屏影像上的小字**：故事区标签使用深色底板 + 红色竖线，保证压在照片高光上仍可读。

## 资源与路径

- 所有页面之间的链接、图片、CSS / JS / 字体引用**一律使用相对路径**，
  不含本机绝对路径，也不含 `file://`。
- 页面内**不存在任何绝对 URL**：没有 `http(s)://` 外链，也没有 `mailto:`。
  邮箱与仓库地址在 HTML 里是页内锚点与纯文本，由 `assets/js/site.js` 在点击时
  组装邮件客户端链接；仓库地址通过「复制」按钮取用。
- 字体自托管于 `assets/fonts/`（Anton、Archivo、Noto Serif SC），不依赖外部 CDN。
- 页面结构清晰、标签使用规范；每个 `img` 都带 `width` / `height`，避免布局跳动。
- `.gitattributes` 规定所有文本资源以 LF 存储，网页源码在仓库与线上完全一致。

## 素材来源与整理

原片是摄影师自己的四个主题文件夹加一张人物照，存放于 `D:\photo`：

| 文件夹 | 对应系列 | 帧数 |
| --- | --- | --- |
| `set1 刚开始接触相机` | 01 初 | 14（卷一 6 帧 + 卷二 8 帧） |
| `set2 在学校的日常` | 02 日 | 16 |
| `set3 旅游` | 03 旅 | 16 |
| `set4 古庙` | 04 庙 | 9 |
| `作者` | 摄影师介绍人物像 | 1 |

`set1` 中另有 8 个 `retouch_*.jpg`：白花、松针、园墙、花束、相册墙、花摊，
每一张都烧着摄影师自己打的 "Pe.Daphine vortex 2023" 水印。它们与前六帧同出一源，
按创作者的决定保留在作品集中，并在「初」系列的卷二单独成卷——
前面有一道分隔页（`SPLITS` 分隔块 + 独立的图注）说明这一卷的内容与水印来路。
页脚声明保持「所有影像由摄影师拍摄与处理」。
`tools/excluded_sheet.py` 会生成一张联页图，把这批照片逐张列出来核对。

器材与年份均以文件 EXIF 为准：Olympus E-M10（校园、古庙、远行主力）、
OPPO A9x（2022 年第一批）、iPhone（2026 年路上的随手拍）、DJI Mini 微型无人机
（2026 年旅途中的两张航拍，以及那张水边人物照）。

`tools/` 中的脚本完成了全部素材整理：

- `tools/build_assets.py` — 扫描原片目录，按系列挑选并重新编号，
  统一施加一次对比度 / 饱和度校准（让两台机器、四个年份的素材看起来像同一次展览），
  输出 1800px / 1400px / 2600px 三档网页用渐进式 JPEG，
  同时生成 24px 模糊占位图。
- `tools/build_site.py` — 由结构化数据生成全部 9 个页面，
  保证导航、页脚、图注与元数据在每个页面完全一致。
- `tools/audit_site.py` — 交付前自检：检查所有引用是否为相对路径、
  目标文件是否存在、每个页面是否能从 `index.html` 到达。
- `tools/exif_dump.py` — 导出每张原片的机型、拍摄时间与尺寸，用于核对年份与器材。
- `tools/label_sheet.py` — 生成带图注的联页图，逐帧核对图注与画面是否相符。

## 交付自检

`tools/` 下的脚本覆盖了从本地到线上的每一道关卡：

| 脚本 | 作用 |
| --- | --- |
| `audit_site.py` | 本地：引用是否全为相对路径、目标是否存在、页面是否互达 |
| `qa_mobile.py` | 真机窄屏（390px）与桌面（1440px）逐页测量：横向溢出、破图、图片解码 |
| `measure_plates.py` | 量出每张图版实际渲染的宽高，确认照片没有大过屏幕 |
| `shoot.py` / `shoot_mobile.py` / `shoot_scroll.py` | 桌面、窄屏与首屏以下区块截图，用于视觉走查 |
| `section_map.py` | 量出各区块的实际纵向位置，供滚动截图对准 |
| `verify_live.py` | 公网抓取：页面状态码、每个资源的状态码、绝对路径泄漏 |
| `final_check.py` | 线上验收：页面、资源、路径、行尾、首页链接、外链依赖 |
| `diff_live.py` | 逐字节比对线上文件与仓库文件，确认发布的是同一份 |
| `blob_check.py` | 直接读取 git blob 字节，核对仓库内存储的行尾 |

窄屏检查需要特别说明：Edge 无头模式会把窗口宽度钳制在约 504px，
用 `--window-size=390` 截出来的其实是一张 504px 版面再裁切到 390px 的假图。
`qa_mobile.py` 改用固定宽度的 iframe 渲染，得到真正的 390px 视口，
因此报告里的 `innerWidth` 与溢出数据是可信的。
